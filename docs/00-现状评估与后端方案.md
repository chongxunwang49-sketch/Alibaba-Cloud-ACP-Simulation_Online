## 3. 需要新增的 API（v1 契约，待确认）

### 3.1 全局约定

```text
Base URL : /api           # 前端 baseURL 固定 /api，由 Nginx 反代到 127.0.0.1:3004
编码      : application/json; charset=utf-8
身份      : 请求头 X-Client-Id: <uuid v4>（前端 localStorage 生成一次，永久复用）
            服务端按 clientId upsert 匿名用户，免登录；后续可平滑升级为账号绑定
成功响应  : { "data": ... }
失败响应  : { "error": { "code": "NOT_FOUND", "message": "题目不存在" } }
错误码    : VALIDATION_ERROR / CLIENT_ID_REQUIRED / NOT_FOUND /
            EXAM_ALREADY_SUBMITTED / EXAM_NOT_SUBMITTED / RATE_LIMITED / INTERNAL
分页      : ?page=1&pageSize=20（默认 20，上限 50）
```

### 3.2 路由清单

| # | 方法 | 路径 | 用途 | 要点 |
| --- | --- | --- | --- | --- |
| 1 | GET | `/api/health` | 健康检查 | 返回 db 连接状态，供部署脚本/巡检使用，无需身份 |
| 2 | GET | `/api/meta` | 考试配置 + 题库统计 + 六大板块比例 | 板块比例是**考纲常量**（17/15/20/16/16/16），不是题库真实分布 |
| 3 | GET | `/api/questions` | 题库分页浏览 | 过滤 `type/topic/keyword`，排序稳定；**不下发 answer/explanation** |
| 4 | GET | `/api/questions/:id` | 单题详情（练习页刷新/深链） | 同上，不含答案 |
| 5 | GET | `/api/practice/set` | 生成一次专项练习（如 20 题） | `topic/type/count`；服务端随机抽取，返回不含答案 |
| 6 | POST | `/api/practice/answer` | 提交单题，即时判分 | 返回 `correct/answer/explanation`；写答题记录 + 错题本 |
| 7 | POST | `/api/exams` | 开考：50 单选 + 25 多选组卷 | 试卷**快照**落库，返回 `examId` 与无答案题目；201 |
| 8 | GET | `/api/exams/:id` | 恢复未交卷试卷 | 用于刷新/断线续考（按 `startedAt` 还原用时） |
| 9 | POST | `/api/exams/:id/submit` | 交卷 | 服务端判分、幂等（重复提交返回同一结果，不重复计错） |
| 10 | GET | `/api/exams/:id/report` | 交卷后逐题解析 | 未交卷访问 → 409；含你的作答/正确答案/解析 |
| 11 | GET | `/api/exams` | 历史成绩（表格） | 分页，按 `submittedAt` 倒序 |
| 12 | GET | `/api/wrong-questions` | 错题本（表格） | `topic/type/mastered` 过滤；含题干摘要、错误次数、最近错误时间 |
| 13 | PATCH | `/api/wrong-questions/:questionId` | 标记"已掌握" | `{ "mastered": true }` |
| 14 | DELETE | `/api/wrong-questions/:questionId` | 移出错题本 | 物理删除该用户下的错题记录 |
| 15 | GET | `/api/stats/overview` | 首页数据卡 | 已答题数、正确率、错题数、考过次数、最高分、六大板块掌握度、近 7 天趋势 |

> P2（先不做，接口预留）：`PATCH /api/exams/:id/answers` 单题自动保存（防刷新丢进度）；`GET /api/questions/search` 全文检索。

### 3.3 数据模型（MongoDB 集合）

```js
// questions —— 由 questions.json 导入，只读
{ id: "q001", type: "single|multiple", topic: "app-dev|prompt|rag|finetune|agent|prod",
  question: "...", options: ["A 文本", "..."], answer: ["A","C"],   // 统一字母数组
  explanation: "...", source: "...", sourceUrl: "..." }

// users —— 匿名设备用户
{ clientId: "uuid", nickname: null, createdAt, lastSeenAt }

// exams —— 试卷快照（题目顺序/分值固化，保证复盘与补算一致）
{ clientId, status: "ongoing|submitted",
  paper: [{ questionId, type, topic, points, order }],
  startedAt, submittedAt, durationSec,
  answers: [{ questionId, selected: ["A"], correct: true }],
  score, correctCount, wrongCount, byTopic: [{ topic, total, correct }] }

// answer_records —— 逐题作答流水（练习 + 考试）
{ clientId, questionId, selected: ["A"], correct: bool,
  mode: "practice|exam", examId: null, createdAt }

// wrong_questions —— 错题本聚合
{ clientId, questionId, wrongCount, lastSelected: ["B"],
  lastWrongAt, mastered: false, updatedAt }
```

索引：

```text
questions        : { id: 1 } unique, { topic: 1, type: 1 }
exams            : { clientId: 1, submittedAt: -1 }
answer_records   : { clientId: 1, createdAt: -1 }, { clientId: 1, questionId: 1 }
wrong_questions  : { clientId: 1, questionId: 1 } unique, { clientId: 1, mastered: 1, lastWrongAt: -1 }
```

### 3.4 为什么这样设计（关键取舍）

1. **答案不下发、服务端判分**：现在 `index.html` 里答案随页面一起可读，任何人 F12 就能拿全库答案，面试演示时是硬伤。改为 `/api/questions` 不含 `answer/explanation`，判分只在提交后返回，既防扒题，也让"提交后右侧展开解析"的交互天然成立。
2. **用 `X-Client-Id` 匿名身份，不做登录**：面试官打开就是干净状态，不需要注册；后端仍能持久化错题本与成绩，且 `users._id` 已留好，后续加账号只需绑定。
3. **试卷快照落库**：随机组卷必须固化，否则中途题库变更/重算会导致复盘题号错位；同时支持刷新续考。
4. **交卷幂等**：双击、断网重试、PM2 重启都可能重复提交，用 `exams.status` 判定，重复请求返回同一份成绩，避免错题次数被刷高。
5. **分页 + 6 个展示接口都要压包**：1 Mbps 带宽下 695 KB 题库首屏需 ~5.6 s，不满足"首屏 < 2 s"；改为接口分页 + Nginx gzip 后，单页 JSON 约 10–30 KB。
6. **导入用 upsert，不用 `--drop`**：便于重复执行和多环境同步；`questions.id` 唯一索引保证幂等。

   - `server/data/questions.ndjson`（逐行 JSON，适合增量 upsert）
   - `server/data/questions.array.json`（JSON 数组，适合 `--jsonArray`）
   - 屏幕打印统计与异常清单（当前数据校验结果为 0 异常）。
2. 服务器导入（二选一）：
   ```bash
   # 全量重建（会重建集合，索引由应用启动时 createIndexes 恢复）
   mongoimport --uri "mongodb://127.0.0.1:27017/acp" \
     --collection questions --file data/questions.array.json --jsonArray --drop

   # 增量/幂等（文档 _id 即题库 id，如 q001）
   mongoimport --uri "mongodb://127.0.0.1:27017/acp" \
     --collection questions --file data/questions.ndjson \
     --mode=upsert --upsertFields=_id
   ```
3. **兜底：应用启动自举（seed）**。`yum` 装 `mongodb-org-server` 默认**不带** `mongodb-database-tools`（`mongoimport` 在另一个包里，CentOS 源不一定有），只依赖 mongoimport 会让"一键部署"在服务器上偶发失败。因此后端启动时若 `questions` 为空，自动 `bulkWrite` upsert 导入，并 `createIndexes`；`SEED_FORCE=1` 可强制重刷。
4. 说明：MongoDB 6+ 的命令行是 `mongosh`，`mongo` 旧 shell 已移除；脚本里要按实际版本选择。

### 5.2 `.env` 设计（本地/线上分离）

- `.env.example` 提交仓库；`.env` 进 `.gitignore`（避免把线上连接串推上公网）。

### 5.3 PM2

- `name: acp-api`、`script: src/server.js`、`cwd: /opt/acp/server`
- **`instances: 1`、`exec_mode: fork`**：2 GiB 内存与 MongoDB 同机，cluster 会翻倍内存并让内存限流计数失真。
- `max_memory_restart: 300M`、`time: true`；`pm2 startup systemd` + `pm2 save` 保证重启自恢复。

### 5.4 Nginx 要点

- `location /api/ { proxy_pass http://127.0.0.1:3004; }` —— **结尾不带 `/`**，保留 `/api` 前缀交给 Express 挂载；写成带 `/` 会剥掉前缀，后端就 404。
- `try_files $uri $uri/ /index.html;` 处理 Vue history 模式；`/assets/` 长缓存、`index.html` 不缓存。
- `gzip on` 覆盖 `js/css/json/svg`，1 Mbps 下这是首屏达标的必要条件。

### 5.5 `deploy.sh` 流程

```text
本地构建 dist → tar 打包（排除 node_modules/.env/日志）
  → ssh 预检（目录/权限/pm2/node 版本）
  → 上传 dist + server 代码
  → 服务器：npm ci --omit=dev（需提交 package-lock.json）
  → pm2 startOrReload ecosystem.config.js --env production && pm2 save
  → curl -fsS http://127.0.0.1:3004/api/health 失败即非 0 退出
```

变量全部走环境变量（`DEPLOY_HOST/DEPLOY_USER/DEPLOY_PORT/SSH_KEY/REMOTE_DIR`），`set -euo pipefail`，无交互密码。

### 6.1 技术风险（部署前必须确认）

| 风险 | 说明 | 处理 |
| --- | --- | --- |
| CentOS 7 + Node 18/20/22 | Node 18+ 官方 linux-x64 二进制要求 **glibc ≥ 2.28**，CentOS 7 是 2.17，NVM 直装会报 `GLIBC_2.28 not found` | 按 `cat /etc/redhat-release` 定：CentOS 7 → unofficial `glibc-217` 构建的 Node 22.20.0（备选官方 16.20.2，已 EOL）；Alibaba Cloud Linux 3/CentOS 8+ → Node 22 官方包 |
