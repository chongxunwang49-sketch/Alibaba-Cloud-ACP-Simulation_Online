# 部署手册（阿里云 ECS：Alibaba Cloud Linux 3 / Ubuntu 22.04 / CentOS 7）

> **已归档**：本手册是宿主机裸装方案（Node + PM2 + 系统 Nginx），相关脚本已移到
> `deploy/legacy-host/`。主部署路径已改为 Docker Compose，见 [04-Docker部署.md](04-Docker部署.md)。
> 本文仅作回退参考。

目标架构：

```
用户浏览器 ──80──> Nginx ──静态──> /var/www/acp/dist (Vue 构建产物)
                     └──/api──> 127.0.0.1:3004 (Node/Express, PM2 守护)
                                      └──> 127.0.0.1:27017 (MongoDB)
```

对外只开 **22 / 80**；3004 与 27017 只监听本机，安全组不放行。

---

## 0. 先选系统

| 系统 | 推荐 | Node | MongoDB | 说明 |
| --- | --- | --- | --- | --- |
| **Alibaba Cloud Linux 3** | ★★★ | 官方 22.x 二进制 | 7.0 | RHEL 8 兼容，glibc 2.28+，步骤最少 |
| **Ubuntu 22.04** | ★★★ | NodeSource 22 | 7.0 | apt 安装，资料多 |
| CentOS 7.9 | ★★ | unofficial glibc-217 22.20.0 | 4.4 | 已 EOL，需绕过 glibc 2.17，仅兼容用 |

> MongoDB 5.0+ 要求 CPU 支持 AVX。极老实例若 `mongod` 启动报 `Illegal instruction`，改用 4.4 或换实例规格。
> 第 1–4 节按系统给出分支，其余章节通用。

## 1. 前置条件

| 项 | 要求 |
| --- | --- |
| 系统 | Alibaba Cloud Linux 3 / Ubuntu 22.04 / CentOS 7.9，x86_64，2 vCPU / 2 GiB 起 |
| 安全组 | 入方向仅 22、80 |
| 软件 | Node.js 22.x、MongoDB 7.0（CentOS 7 用 4.4）、Nginx、PM2、curl/tar/rsync |

登录后先装基础工具并加 swap（2 GiB 内存建议 2 GiB swap，避免 `npm ci` 时 OOM）：

```bash
# yum 系（Alibaba Cloud Linux 3 / CentOS 7）
yum install -y curl tar rsync xz

# Ubuntu
apt-get update && apt-get install -y curl tar rsync xz-utils

# 通用：2 GiB swap
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
free -m
```

## 2. 安装 Node.js

后端要求 Node >= 16.20.1，建议 22.x。按系统选一种：

### 2.1 Alibaba Cloud Linux 3 / CentOS 8+

```bash
cd /usr/local
NODE_VER=v22.20.0
curl -fSLO "https://nodejs.org/dist/$NODE_VER/node-$NODE_VER-linux-x64.tar.xz"
curl -fSLO "https://nodejs.org/dist/$NODE_VER/SHASUMS256.txt"
grep "linux-x64.tar.xz" SHASUMS256.txt | sha256sum -c -
tar -xJf "node-$NODE_VER-linux-x64.tar.xz"
mv "node-$NODE_VER-linux-x64" nodejs
ln -sf /usr/local/nodejs/bin/node /usr/local/bin/node
ln -sf /usr/local/nodejs/bin/npm  /usr/local/bin/npm
ln -sf /usr/local/nodejs/bin/npx  /usr/local/bin/npx
node -v
```

### 2.2 Ubuntu 22.04

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt-get install -y nodejs
node -v
```

### 2.3 CentOS 7（glibc 2.17 关键坑）

CentOS 7 的 glibc 是 2.17，而 Node 18+ 的**官方**二进制要求 glibc 2.28，直接跑会报
`GLIBC_2.28 not found`。用 unofficial-builds 提供的 glibc-217 构建（同源编译，仅链接旧 glibc）：

```bash
yum install -y xz
cd /usr/local
NODE_VER=v22.20.0
BASE="https://unofficial-builds.nodejs.org/download/release/$NODE_VER"
PKG="node-$NODE_VER-linux-x64-glibc-217"

curl -fSLO "$BASE/$PKG.tar.xz"
curl -fSLO "$BASE/SHASUMS256.txt"
grep "linux-x64-glibc-217.tar.xz" SHASUMS256.txt | sha256sum -c -

tar -xJf "$PKG.tar.xz"
mv "$PKG" nodejs
ln -sf /usr/local/nodejs/bin/node /usr/local/bin/node
ln -sf /usr/local/nodejs/bin/npm  /usr/local/bin/npm
ln -sf /usr/local/nodejs/bin/npx  /usr/local/bin/npx
node -v   # v22.20.0
```

> 备选：官方 `node-v16.20.2-linux-x64.tar.xz` 是最后一个能在 glibc 2.17 上跑的官方版本（已 EOL），
> 只在无法使用 unofficial 构建时使用。

后端依赖兼容 Node 16.20.1+（Express 4、Mongoose 8.24），已在 Node 22/24 上验证；不要升级到
Mongoose 9（要求 Node 20.19+ 且改动较大）。

## 3. 安装 MongoDB

### 3.1 Alibaba Cloud Linux 3（7.0）

```bash
cat > /etc/yum.repos.d/mongodb-org-7.0.repo <<'EOF'
[mongodb-org-7.0]
name=MongoDB Repository
baseurl=https://repo.mongodb.org/yum/redhat/8/mongodb-org/7.0/x86_64/
gpgcheck=1
enabled=1
gpgkey=https://www.mongodb.org/static/pgp/server-7.0.asc
EOF

yum install -y mongodb-org
```

### 3.2 Ubuntu 22.04（7.0）

```bash
curl -fsSL https://www.mongodb.org/static/pgp/server-7.0.asc \
  | gpg --dearmor -o /usr/share/keyrings/mongodb-server-7.0.gpg
echo "deb [ signed-by=/usr/share/keyrings/mongodb-server-7.0.gpg ] https://repo.mongodb.org/apt/ubuntu jammy/mongodb-org/7.0 multiverse" \
  > /etc/apt/sources.list.d/mongodb-org-7.0.list
apt-get update && apt-get install -y mongodb-org
```

### 3.3 CentOS 7（4.4）

CentOS 7 用官方 4.4 仓库（7.0 已不支持 CentOS 7）：

```bash
cat > /etc/yum.repos.d/mongodb-org-4.4.repo <<'EOF'
[mongodb-org-4.4]
name=MongoDB Repository
baseurl=https://repo.mongodb.org/yum/redhat/$releasever/mongodb-org/4.4/x86_64/
gpgcheck=1
enabled=1
gpgkey=https://www.mongodb.org/static/pgp/server-4.4.asc
EOF

yum install -y mongodb-org
```

限制内存占用（2 GiB 机器必须做，默认会吃掉一半内存）：

```bash
# /etc/mongod.conf
net:
  port: 27017
  bindIp: 127.0.0.1
storage:
  dbPath: /var/lib/mongo
  wiredTiger:
    engineConfig:
      cacheSizeGB: 0.5
```

```bash
systemctl enable --now mongod
systemctl status mongod --no-pager
```

> 数据只从本机访问，且 27017 不对外，可先不开鉴权；如后续要多机访问，再启用 `security.authorization` 并建账号。

## 4. 安装 Nginx 与 PM2

```bash
# yum 系（Alibaba Cloud Linux 3 / CentOS 7）
yum install -y epel-release nginx

# Ubuntu
apt-get install -y nginx

systemctl enable --now nginx
npm install -g pm2@5
pm2 -v
```

云安全组之外，系统防火墙也要放行 80：

```bash
# firewalld（yum 系）
firewall-cmd --permanent --add-service=http && firewall-cmd --reload

# ufw（Ubuntu，若启用）
ufw allow 80/tcp
```

## 5. 首次部署

### 5.0 上线前自检

在服务器上（仓库任意位置）：

```bash
bash deploy/preflight.sh
```

只读检查系统/内存/端口/Mongo/Nginx/PM2，出现 `[FAIL]` 先修复，全部通过再继续。

### 5.1 方式 A：本地一键推送（推荐）

本机没有 bash 时用 PowerShell 版（Windows 10+ 自带 OpenSSH 与 tar 即可）：

```powershell
cd "C:\Users\DELL\Desktop\阿里云ACP模拟_线上"

# 先构建前端（Workbuddy 的 Vue 项目）
cd frontend; npm install; npm run build; cd ..

powershell -ExecutionPolicy Bypass -File deploy\push.ps1 `
  -Server root@47.xx.xx.xx `
  -Key "$HOME\.ssh\id_ed25519"
```

有 Git Bash / WSL 时等价：

```bash
cd "C:/Users/DELL/Desktop/阿里云ACP模拟_线上"

# 先构建前端（Workbuddy 的 Vue 项目）
cd frontend && npm install && npm run build && cd ..

DEPLOY_HOST=root@47.xx.xx.xx \
DEPLOY_SSH_KEY=~/.ssh/id_ed25519 \
bash deploy/deploy.sh
```

> 前端还没构建出 `frontend/dist` 时，先只上后端与 API：PowerShell 加 `-SkipWeb`，bash 用 `SKIP_WEB=1`；
> 等前端完成后去掉再跑一次即可（会覆盖静态目录）。

脚本做的事：

1. 本地打包（排除 `node_modules`、`.env`、`.git`、Edge 调试配置与截图）→ `scp` 到服务器 `/tmp`；
2. 远端解压到 `/opt/acp`，进入服务器模式；
3. `server/.env` 不存在时从 `.env.example` 生成（默认连本机 Mongo）；
4. `npm ci --omit=dev`；
5. `pm2 startOrReload deploy/ecosystem.config.js --update-env` + `pm2 save`；
6. 若找到 `frontend/dist`（或 `dist`/`web/dist`/`ACP模拟/dist`），发布到 `/var/www/acp/dist`；
7. 安装 `deploy/nginx.conf` 到 `/etc/nginx/conf.d/acp.conf`（先备份移走 `default.conf`），`nginx -t` 后 reload；
8. `curl http://127.0.0.1:3004/api/health` 重试 15 次，失败即退出。

可选环境变量：`DEPLOY_DIR`（默认 `/opt/acp`）、`WEB_ROOT`（默认 `/var/www/acp/dist`）、`WEB_DIST`、`SKIP_NGINX=1`、`SKIP_WEB=1`、`HEALTH_URL`。

### 5.2 方式 B：服务器上直接部署

```bash
mkdir -p /opt/acp && cd /opt/acp
# git clone 或 scp 上传仓库后：
bash deploy/deploy.sh
```

### 5.3 开机自启

```bash
pm2 startup systemd -u root --hp /root   # 按输出提示执行那一行命令
pm2 save
systemctl is-enabled pm2-root
```

## 6. 环境变量（`server/.env`）

由 `.env.example` 生成，按需修改后 `pm2 restart acp-api --update-env`。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `NODE_ENV` | `production` | 生产必须 production |
| `PORT` | `3004` | Node 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `MONGODB_URI` | `mongodb://127.0.0.1:27017/acp` | 数据库连接 |
| `SEED_ON_START` | `true` | 启动时题库为空则自动导入 |
| `SEED_FORCE` | `false` | 置 1 强制用打包数据覆盖题库 |
| `CORS_ORIGIN` | 空 | 同源部署留空；前后端分离时填前端域名（逗号分隔，或 `*`） |
| `TRUST_PROXY` | `1` | 位于 Nginx 后，限流取真实 IP |
| `APP_TIMEZONE` | `Asia/Shanghai` | 统计按该时区分日 |
| `RATE_LIMIT_DISABLED` | `false` | 压测时可临时关闭 |

> 安全提示：`server/.env` 不要提交到仓库、不要打进部署包（脚本已排除）。本地开发若无法创建 `.env`，`server/src/config/env.js` 会用开发默认值（27017、seed 开启）。

## 7. 验证清单

```bash
# 0. 上线自检（只读，有 FAIL 退出 1）
bash deploy/preflight.sh

# 1. 后端健康
curl -s http://127.0.0.1:3004/api/health | head -c 300; echo

# 2. 题库已导入（total 应为 951）
curl -s http://127.0.0.1:3004/api/meta | head -c 500; echo

# 3. 进程与端口
pm2 status acp-api
ss -lntp | grep -E '3004|27017|80'

# 4. 前端与反代
curl -sI http://127.0.0.1/ | head -1
curl -s http://127.0.0.1/api/meta | head -c 200; echo
```

浏览器打开 `http://<公网IP>/`，走一遍：首页 → 模拟考开考（75 题）→ 交卷出分 → 报告 → 错题本 → 刷新页面数据仍在（`X-Client-Id` 存在 localStorage）。

## 8. 日常运维

```bash
pm2 logs acp-api --lines 100      # 日志
pm2 restart acp-api --update-env  # 改 .env 后
pm2 monit                          # 资源
nginx -t && systemctl reload nginx

# 备份（每天一次即可）
mongodump --uri "mongodb://127.0.0.1:27017/acp" --out /root/backup/$(date +%F)
```

更新代码：本地改完 → 重新 `npm run build`（前端）→ 再跑一次 `deploy\push.ps1`（或 `DEPLOY_HOST=... bash deploy/deploy.sh`）。题库有变时重新 `cd server && npm run export:bank`，部署后 `SEED_FORCE=1 pm2 restart acp-api --update-env`（或 `mongoimport --mode=upsert --upsertFields=_id`）。

## 9. 故障排查

| 现象 | 原因 / 处理 |
| --- | --- |
| `GLIBC_2.28 not found` | 装了 Node 18+ 官方包，按第 2 节换 glibc-217 构建 |
| `mongod` 启动报 `Illegal instruction` | CPU 不支持 AVX，MongoDB 5.0+ 用不了：换 4.4 或换实例规格 |
| Windows 提示 `bash` 不是内部或外部命令 | 本机没有 bash：用 `deploy\push.ps1`，或直接在服务器上执行 `deploy.sh` |
| `502 Bad Gateway` | 后端没起：`pm2 status`、`pm2 logs acp-api`、`ss -lntp | grep 3004` |
| `/api/health` 返回 503 `NOT_READY` | MongoDB 没起：`systemctl status mongod`、看 `MONGODB_URI` 是否写错 |
| 页面 404 / 刷新 404 | Nginx 缺 `try_files ... /index.html`，确认 `deploy/nginx.conf` 已安装 |
| 打开是 Nginx 欢迎页 | 系统 `default.conf` 仍在抢 80，移走并 reload |
| 外网能访问 3004 | 安全组放了 3004，删掉该规则（只留 22/80） |
| 首屏慢 | 确认 Nginx `gzip on` 生效、前端产物已压缩、API 分页且不返回答案 |
| npm ci 被 OOM kill | 加 swap，或临时 `NODE_OPTIONS=--max-old-space-size=512` |
| `mongod` 常被 OOM | `cacheSizeGB: 0.5`，并确认 swap 生效 |
| PM2 重启后丢失 | 忘了 `pm2 save` / `pm2 startup` |
